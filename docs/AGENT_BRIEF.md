# Brief for agents building Oxide screens

Oxide is an Expo SDK 58 / React Native 0.88 / TypeScript app (Android first) for learning Rust:
the Rust Book, Rustlings exercises and a terminal with a real on-device toolchain.
Repo `/home/claude/repo`, branch `expo-app`. Several agents work in parallel — stay inside your scope.

  at the 412 × 915 dp reference: copy sizes, paddings, gaps, radii, colors, font sizes/weights,

## Rules
- **Production app, real data.** No hard-coded sample user/progress (no "Sam", no "26 of 95" literals).
  Everything comes from `useApp` + selectors + content. The prototype's numbers are what the demo seed
  (`demoState()` in `src/state/app.ts`, web `?demo=1`) produces — use it to compare your screen with the
  prototype. Day-1 ("fresh") variants come from a new user's real state.
- Copy text exactly from the prototype/spec (curly quotes ’ “ ” and the · separator included).
- Touch targets ≥ 44 dp. Use `Press` for every tappable thing so press/hover feedback matches.
- RN differences: no CSS inset shadows (use `Inset`), no conic-gradient (use `Ring`/SVG), no `gap` issues
  (RN 0.88 supports `gap`), `fontWeight` must come from the font helpers (custom fonts need family per weight).
- Keep shared files unchanged. If you truly need a shared change (e.g. a new action in `state/app.ts`, a
  new helper in `ui/`), make it small and additive and list it in your report.
- Typecheck: `npx tsc --noEmit` — fix errors in your files; ignore errors in files other agents are writing.
- Web preview for checking: `npx expo export --platform web` or `npx expo start --web --port 8081`
  and Playwright (`require('playwright')`, chromium preinstalled). docs.expo.dev is unreachable — read
  `.d.ts` files in node_modules for APIs. `npx expo install` needs `EXPO_OFFLINE=1`.
- Commit only your own files (`git add <paths>`; retry if `.git/index.lock` exists). Commit trailer:


- Final report: files, what's done vs. not, deviations from the prototype and why, shared-file changes,

## Cross-agent contracts
- Popup opts (implemented by the Overlays agent in `src/overlays/`):
  `goal` {} · `reminder` {} · `solution-setting` {} · `solution-early` { exercise: string, attempts: number, onShow: () => void } ·
  `dlfail` { remainingMB: number, onWait: () => void, onMobile: () => void } · `delproj` { name: string, onDelete: () => void } ·
  `signout` {} · `delacct` {} · `exmenu` { exercise: string, onReset: () => void } ·
  `cmd` { command: string, meta: string, output: string[] } · `display` {} · `streak` {} · `xp` {} ·
  `report` { exercise?: string, code?: string } · `mission` {} (reads today's mission from state) ·
  `levelup` { level: number } · `push` {}.
- Rendered inside their own screens (not popups): Onboarding's notification-permission dialog
  (use the real `expo-notifications` permission request on Android; draw the prototype's dialog on web) and
  the Terminal projects sheet.
- `src/state/reminders.ts` (Onboarding agent): `scheduleReminder(time: string | null): Promise<void>` using
  expo-notifications daily trigger; Overlays/Settings call it.
- `src/fs/index.ts` (Terminal agent): sandbox file system over expo-file-system with shell paths:
  `expand(path, cwd)`, `list(path)`, `read(path)`, `write(path, text)`, `exists(path)`, `remove(path)`,
  `mkdirp(path)`, `listProjects(): Promise<{ name: string; files: string[]; bytes: number }[]>`,
  `createProject(name)` (same files as `cargo new`), `deleteProject(name)`, `restoreProject(name)` (undo).
  On web it falls back to an in-memory FS persisted in AsyncStorage.
- `src/ui/CodeEditor.tsx` (Practice/Exercise agent): editable highlighted code editor + key row, used by
  Workspace and Editor.
- Terminal accepts `entry.params = { cwd?: string, run?: string }` to start in a folder and run a command
  (used by Editor "Run", Project, Profile's fixed errors → `rustc --explain E0382`, Exercise menu).
